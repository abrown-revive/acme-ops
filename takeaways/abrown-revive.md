# abrown-revive's Takeaways

Key things I took away from [Tool School: GitHub 101](https://hannahstulberg.substack.com/p/tool-school-github-101):

1. **GitHub isn't just for engineers.** Any shared knowledge work, like specs, playbooks and docs, benefits from version history, review before changes go live, easy rollback, and a way to collaborate without overwriting each other.

2. **It's Google Drive with guardrails.** A repo is a project folder, a commit is a named version, a branch is "make a copy," `main` is the shared doc everyone trusts, and a pull request is "please comment before I finalize."

3. **The daily rhythm is six steps:** branch → edit → commit → push → open a PR → merge. Pull the latest from `main` before starting so you run into fewer conflicts.

4. **Commit early, commit often.** A commit is a checkpoint, not a finished product. Commit when something works and before trying something risky, and write specific messages ("Update vendor contacts for Q2", not "Fixed stuff").

5. **Pushing and opening a PR are different.** Pushing saves your work to the cloud. Opening a PR is raising your hand to say "this is ready for eyes."

6. **Git errors are scarier than they are.** Git is built to be recoverable, so a scary message almost never means lost work. If I'm stuck, I can describe the error to Claude Code.

7. **It matters more as teams go AI-native.** Shared CLAUDE.md files, skills, and edits made by AI agents all need one versioned, reviewable home, and GitHub is that home.
